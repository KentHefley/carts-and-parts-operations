# Calendar implementation milestone

Approved October 12: management colors identify people; employee-calendar colors identify categories. Both calendars filter by one/multiple people with All People and Clear Filters. Management events with multiple people use the primary person's color; unassigned events are neutral. Administrators edit person colors. Names and titles remain visible.

Plan: reuse a shared FullCalendar Standard foundation for both calendars, with Month/Week/Day, ellipsis event bars, three bars plus +N more opening Day, detail/editor overlay, private authenticated server reads, admin-only mutations, durable audit history and revision conflict protection. Keep all-day dates separate from timed events and never derive events from sales orders. Include employees without login accounts through a directory separate from login approval. No Monday import or writes.

Acceptance: approved users view/filter only; admins create/edit/delete, manage employee-category labels/colors and person colors. Enforce permissions on the server. Preserve people/categories referenced by historical events. Reject invalid date ranges and stale edits; retain input on save failure. Use location time zones in event details, keep all-day dates stable, and explain the calendar grid's display time zone. Confirm recurrence patterns/exceptions and event fields before implementing dependent behavior.

Verification: synthetic permission/conflict/idempotency tests; one-occurrence/series edits and deletions once recurrence rules are approved; all-day and multi-day boundaries, daylight saving ambiguity/nonexistent times, people/category filters and color contrast. Actual-component browser checks for overflow, +N more, keyboard/modal focus, phone/tablet and light/dark. Guard development migrations; lint/types/build and Next runtime checks. No commit, push or deployment.

Approved follow-up: Sunday starts the week. Daily, weekly, monthly and yearly repeats have an optional end date; admins edit/delete one occurrence or the entire series. February 29 appears only in leap years. Fields are Title, People (multiple with primary person), Location, start/end dates/times, All Day, Time Zone, Repeat and Notes; employee events additionally have Category.

Implementation notes: monthly dates absent from a month are skipped. Timed repeats preserve local wall-clock time; nonexistent future daylight-saving times are skipped, and ambiguous future times use the earlier instant. Initial ambiguous/nonexistent input is rejected. All-day end dates are inclusive in the editor. Series edits retain saved exceptions. Drag-and-drop is disabled; changes use the editor. Active events are limited to 1,000 per calendar and expansion to 5,000 occurrences per displayed range. New approved accounts gain a linked directory entry when opening a calendar; manually added directory entries do not grant login access.

Inline calendar people (October 13): acceptance is admin select/add directly from event editor, remembered names/colors, reusable suggestions, no login account creation and existing history preserved. Guarded calendar DB tests verify normalized duplicates, retries, parallel creators returning one person, automatic colors and inactive handling; browser fixture verifies selection/suggestions. Signed-in review: add a new person, save an event, reopen and reuse the name on either calendar, check primary-person color, filters and settings color editing. Cancelling an event retains any newly added directory name. Employee calendar colors remain category-based.
